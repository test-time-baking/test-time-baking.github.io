## TL;DR

**Test-time Baking (TTB)** bakes the output of cross-view attention into a small fast-weight MLP, once per scene. Rendering then costs the same at any number of input views, at the quality of the KV-cache model it starts from.

<details>
<summary>Abstract</summary>

Decoder-only Large View Synthesis Models (LVSMs) with KV-cache have recently achieved state-of-the-art quality by regressing novel views from neural networks without reconstructing 3D geometry, while Test-Time Training (TTT) layers save computation but sacrifice quality. We propose Test-Time Baking (TTB), a strategy that learns to bake global scene information from cross-view attention into a lightweight MLP, enabling fast and high-fidelity novel-view decoding. The first key is to repurpose the fast-weight MLP of TTT to learn the cross-view attention mapping explicitly from its input-output pairs, rather than replacing attention entirely, achieving the same rendering efficiency as TTT while delivering substantially higher quality. The second key addresses a modality misalignment between context prefilling and novel-view rendering: we disentangle context tokens into camera-only context rendering tokens to serve as TTB input, and context ground-truth tokens with image content to serve as the TTB mapping target, ensuring the baked MLPs are relieved of the modality generalization challenge between context and novel-view processing. Our method achieves up to 23× rendering speedup with quality on par with the state of the art across several benchmarks.

</details>

## Rendering speed

TTB renders at a constant 23 fps at any number of input views, while a KV-cache model slows to about 1 fps at 64 views.

### Why the KV-cache slows down

Feed-forward view synthesis **reconstructs** a scene once, then **renders** many novel views from that state. A KV-cache model stores the scene as the keys and values of every input token, and every frame attends to all of it: more views, slower frames. TTB bakes the scene into fixed-size fast weights instead, so a frame costs the same at any number of views.

<StateSizeChart />

### Real-time comparison

TTB starts from a KV-cache model (DVSM) and keeps its cross-view attention for reconstruction, so the two render nearly the same image from the same views (under 1 dB apart on DL3DV). The difference is frame time. Both fly the same camera path **in real time**, each showing its newest finished frame: at 64 views the KV-cache manages about 1 fps, TTB 23. At 16 views the KV-cache reaches 4 fps; TTB stays at 23.

## Method

### Baking attention into fast weights

A Test-Time Training (TTT) layer trains its fast weights $\theta$ so an MLP maps keys to values, replacing attention. TTB keeps cross-view attention during reconstruction and changes only the inner loop's **target**: the MLP learns to reproduce the **attention output**. After prefilling the KV-cache is dropped and only the baked weights remain, so rendering costs exactly what TTT costs, with far more scene information in the weights.

<Stage>
<div class="grid gap-4">
  <EqCard kicker="TTT (LaCT)" note="The target is a linear projection of the input tokens.">

$$
\theta \leftarrow \theta - \eta\,\nabla_{\theta}\,\mathcal{L}\big(f_{\theta}(W_k X),\; W_v X\big)
$$

  </EqCard>
  <EqCard kicker="TTB (ours)" ours note="The target is the cross-view attention output, which already aggregates all context views.">

$$
\theta \leftarrow \theta - \eta\,\nabla_{\theta}\,\mathcal{L}\big(f_{\theta}(W_k X),\; \textcolor{#4f7d00}{\mathrm{CrossAttn}(X^{*})}\big)
$$

  </EqCard>
</div>
</Stage>

Saliency shows the difference: a linear-projection target peaks on one context view, the attention target draws on many.

### Context pairing

Context tokens carry **RGB and pose**; novel-view tokens carry **pose only**. TTB splits each context view into a camera-only *rendering* token (the MLP input) and a ground-truth token with image content (the attention target).

$$
X^{(\text{ctx-gt})}_0 = \mathrm{LN}\big(\mathrm{PE}^{(\text{ray})}(P, K) + \mathrm{PE}^{(\text{rgb})}(I)\big), \qquad
X^{(\text{ctx-rend})}_0 = \mathrm{LN}\big(\mathrm{PE}^{(\text{ray})}(P, K)\big)
$$

Each TTB layer bakes the map $X^{(\text{ctx-rend})} \mapsto \mathrm{CrossAttn}(X^{(\text{ctx-gt})})$ and shares the baked MLP with the novel-view tokens, so both stages see the same modality. Reconstruction handles twice the tokens; rendering cost is unchanged.

<Stage width="mid">

    <Fragment slot="caption">**Pipeline.** Each block: intra-view attention, FFN, TTB layer, FFN. Reconstruction bakes the fast-weight MLP once per scene; rendering retrieves scene information from it in $O(1)$. The rendering loss back-propagates through the baking, so training is end to end.</Fragment>

## Benchmarks

## Ablation

Three additive changes turn a TTT replacement into TTB: context pairing, an MSE inner loop with three steps, and the cross-view attention target. Together they close the gap to the KV-cache model at TTT's rendering speed.

<AblationChart />

<details>
<summary>Inner-loop and layer-design ablations</summary>

| Framework | T | Loss | PSNR ↑ | SSIM ↑ | LPIPS ↓ |
| :--- | :---: | :--- | ---: | ---: | ---: |
| TTT | 1 | dot-prod | 23.12 | 0.704 | 0.286 |
| TTT | 3 | MSE | 23.39 | 0.715 | 0.277 |
| TTB-- | 1 | dot-prod | 23.78 | 0.728 | 0.264 |
| TTB-- | 2 | MSE | 24.16 | 0.744 | 0.251 |
| TTB-- | 3 | MSE | 24.22 | 0.747 | 0.248 |
| TTB-- | 5 | MSE | **24.29** | **0.751** | **0.246** |

MSE beats the dot-product loss for both TTT and TTB--; more inner-loop steps give diminishing gains, and $T = 3$ is the sweet spot.

| Feedback | Residual | PSNR ↑ | SSIM ↑ | LPIPS ↓ |
| :---: | :---: | ---: | ---: | ---: |
| ✗ | ✗ | 24.32 | 0.748 | 0.243 |
| ✗ | ✓ | 24.75 | 0.764 | 0.233 |
| ✓ | ✗ | 24.76 | 0.764 | 0.231 |
| ✓ | ✓ | **24.84** | **0.768** | **0.230** |

Residual learning and feedback each add about +0.4 dB; together +0.5 dB.
